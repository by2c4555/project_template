# Working in Project Template

Identify which kind of work the user requested before applying workflow rules.

- **Developing Project Template itself:** start with [the Development Constitution](Workplan/development_constitution/README.md) and follow its reading map and [development protocol](Workplan/development_constitution/DEVELOPMENT_PROMPT.md). Check [conformance status](Workplan/development_constitution/CONFORMANCE.md) before assuming a specified runtime capability exists.
- **Executing a user project through Workplan:** use the current runtime entry point, validated state/contracts, and designated role instructions. The development constitution is design guidance, not a replacement approval or execution ticket.
- **Preparing external Research:** use the Research handoff guidance. Research is input, not runtime authority.

Respect the surrounding platform instructions and the user's existing authorization. Constitution edits require explicit repository-owner authorization; do not request it again when already granted for the task. Preserve unrelated user changes.

Any capable agent/model may develop this repository. Do not assume a particular provider, tools, network, or subagent capability. Use available tools within authorization, verify claims with observed evidence, and state unsupported capabilities or unrun checks plainly.
